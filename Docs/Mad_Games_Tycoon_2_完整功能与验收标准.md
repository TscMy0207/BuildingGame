## 1. 范围、事实与使用约定

### 1.1 开发目标

开发一款以经营游戏公司为主题的模拟经营游戏，覆盖从小型开发工作室到集研发、发行、硬件平台和企业集团于一体的长期经营过程。核心体验对标《Mad Games Tycoon 2》（以下简称“参考作品”）：通过办公室规划、人才培养、产品定位、研发投入、市场判断和资本运作，形成持续反馈的商业决策循环。

“完整”指覆盖参考作品的核心玩法链路及其主要扩展业务，而不是仅完成“造办公室—开发游戏—获得收入”的原型。本文同时拆解支撑这些玩法的界面、存档、多人、数据、测试和发布要求。逐个家具模型、全部题材名称、每一条事件文本等属于内容资产表，本文规定其结构与验收方法，不虚构原作资源全集。

### 1.2 事实与设计分离

- **原作依据**：附录A记录官方商店介绍和开发者公告能确认的功能类别。
- **本项目规格**：除明确标为原作依据的说明外，本文中的公式、状态机、扣费时机、冲突规则、测试数值和性能门槛都是为可开发、可验收而制定的建议规格，不能当作原作内部实现。
- **待验证细节**：原作未公开或本次未实机验证的精确权重、滑条最优值、概率、内容数量和解锁年份，进入待决策清单；不得把玩家攻略中的经验公式直接视为官方规则。
- **工具无关**：购买何种寻路、存档、编辑器或界面插件，不改变本文的业务验收要求。
- **原创内容**：系统设计可参考同类玩法；本项目的名称、美术、音乐、文字、品牌、界面资产另行创作。

### 1.4 统一验收原则

1. 每条需求必须在玩家界面中可操作、可观察；调试工具只用于设置测试前置条件和定位问题。
2. 所有购买、开发、生产、发行、交易和结算均有唯一记录；失败操作不得留下半扣费、半转移状态。
3. 测试使用固定配置版本、固定随机种子和固定操作时间线；比较确定性业务状态，不比较角色动画帧。
4. 测试中给出的金额、日期、技能值是测试夹具，不是正式平衡参数。
5. “存档一致”指实体关系、资金账本、库存、任务、研发、市场、随机状态和业务计时一致；视觉插值可重新建立。
6. 所有阻止操作的条件必须给出中文原因；不能仅让按钮无响应。
7. 跨模块缺陷不能靠某一模块单独通过测试来豁免。

## 2. 玩家目标与核心循环

### 2.1 经营决策层级

| 时间尺度 | 玩家决策 | 系统反馈 |
|---|---|---|
| 即时操作 | 建房、摆设备、分配员工、处理告警 | 可达性、工作效率、需求状态、资金变化 |
| 单个项目 | 选择题材、类型、平台、引擎、规模和设计方向 | 进度、开发点数、缺陷、成本、评价 |
| 月度经营 | 人员扩张、工资、营销、生产、现金安排 | 收支、库存、销量、口碑、流动性 |
| 年度战略 | 科技投入、系列经营、平台选择、发行能力 | 市场地位、粉丝、系列价值、产品组合 |
| 长期扩张 | 主机、自营平台、子公司、知识产权交易 | 生态规模、授权收益、集团利润、竞争格局 |

### 2.2 主循环

市场调研 → 确定产品定位 → 配置办公室与团队 → 研发或授权技术 → 开发和打磨 → 选择发行与生产方案 → 上市销售 → 获得资金、粉丝和经验 → 分析结果 → 调整下一轮投资。

必须存在以下相互约束：高投入挤占现金；赶工缩短工期但增加质量风险；热门平台扩大受众但提高竞争或授权成本；自发行增加控制权和利润空间，同时承担生产、库存和营销风险；主机需要内容生态，自有作品又受平台用户规模影响。

### 2.3 扩展循环

- 员工成长：招聘 → 匹配岗位 → 工作与培训 → 技能和薪资变化 → 更复杂项目。
- 技术积累：研究功能 → 更新引擎 → 自用或授权 → 收入反哺研发。
- 系列经营：原创作品 → 品牌口碑 → 续作、衍生和重制 → 粉丝增长或透支。
- 长线运营：上线网游 → 扩容、维护、更新 → 留存与付费 → 运营成本和关服决策。
- 平台经营：研发硬件 → 定价与发售 → 获取装机量 → 吸引开发者 → 软件促进硬件销售。
- 集团经营：收购 → 制定子公司方针 → 经营和利润回流 → 扩张、整合或出售。

原作依据：官方介绍确认可选起始年代、不同难度及可定制沙盒；具体配置范围见附录A。下表为本项目拟实现规则。

| 编号 | 优先级 | 功能与规则 | 验收标准 |
|---|---|---|---|
| NEW-01 | P0 | 创建公司，输入名称并选择标识、负责人和初始方案 | 必填项、长度和非法字符有校验；完成后公司资料与所有面板一致；重复点击只创建一局 |
| NEW-02 | P1 | 年代化开局；初始科技、平台、设施、工资和成本由起始日期决定 | 对早期与晚期开局分别验证；不可使用未来科技；已到期的历史平台按配置处于可用、退市或历史状态 |
| NEW-03 | P1 | 难度控制初始资源、市场竞争、成本压力和经营容错 | 难度预览展示主要差异；读档保持设置；同一夹具下不同难度产生对应变化，而非只改标签 |

| NEW-05 | P1 | 新手引导覆盖建造、招聘、开发、发行和财务 | 首次流程可独立完成；引导可跳过和重开；卖掉引导家具后能修复步骤，不永久卡住 |

## 4. 时间、暂停与结算

| 编号 | 优先级 | 功能与规则 | 验收标准 |
|---|---|---|---|
| TIM-01 | P0 | 暂停及1、2、3倍速；建造确认可在暂停时执行，业务进度不推进 | 暂停期间等待30秒真实时间，日期、工资、销售和项目进度不变；恢复后无补算真实等待时间 |
| TIM-02 | P0 | 日、周、月、年边界驱动不同结算 | 从边界前一步推进后，每个到期结算仅执行一次；跨越多个边界时无遗漏；月份天数和闰年符合所选日历 |
| TIM-03 | P0 | 业务使用固定模拟步长，不依赖渲染帧数 | 固定种子和相同模拟时刻指令，在30、60、120帧上限及不同倍速运行至同一天，核心业务快照一致 |
| TIM-04 | P0 | 同一时刻采用固定结算顺序和稳定排序 | 收入、到期费用、违约检查及破产判断顺序有记录；测试结果每次一致；不能因对象遍历顺序决定破产 |
| TIM-05 | P1 | 合同、研究、发行、历史事件采用统一模拟时间 | 暂停不消耗期限；加速后截止日仍正确；读档后不会重新获得完整倒计时 |
| TIM-06 | P1 | 长期运行和历史归档 | 自动运行100个游戏年，日期无溢出；仍可查看指定年份获奖与发行记录；历史压缩不影响现有合同 |

建议同日结算顺序：到期状态变化 → 工作和生产产出 → 销售与运营收入 → 工资和周期费用 → 合同及偿债检查 → 风险判断 → 统计归档。该顺序属于本项目规则，后续调整必须更新测试基线。

## 5. 地产、建造与空间布局

### 5.1 地产与网格建造

| 编号 | 优先级 | 功能与规则 | 验收标准 |
|---|---|---|---|
| BLD-01 | P0 | 建造区域、边界、固定障碍和网格坐标 | 边界外、固定障碍内不可放置；世界坐标与网格转换在地图四角及旋转视角下正确 |

| BLD-08 | P1 | 设施升级、淘汰、维护与环境贡献 | 更换设备更新效率、维护和环境值；禁止同一设备同时领取新旧两份效果；旧设施售出后增益消失 |
| BLD-09 | P1 | 无障碍入口、房间可达性与封路保护 | 封住唯一入口时阻止提交或明确进入不可用状态；采用哪种策略必须全局一致，不能静默困住员工 |
| BLD-10 | P1 | 建造反馈、选择层级与遮挡处理 | 墙、门、家具可独立选中；隐藏墙体只影响显示；鼠标在界面上不会误卖场景物件 |

### 5.2 房间类型与业务能力

下表是房间职责划分，不声称对应原作内部类名。房间是否有效取决于区域合法、入口可达、必要设备存在及所需岗位满足。

| 营销办公室 | 宣传活动与市场相关工作 | 活动完成改变曝光，形成营销支出 |
| 客服支持设施 | 售后、玩家维护、服务能力 | 待处理量变化，并反馈满意度或流失 |
| 培训室 | 员工技能培训 | 学员技能增长且不同时贡献生产 |
| 休息、餐饮、卫生设施 | 满足精力、饮食、卫生等需求 | 员工进入使用状态并恢复对应需求 |
| 清洁及维修能力 | 处理污染、故障和环境问题 | 脏污/故障被清除，维护人员状态可查看 |
| 生产及仓储区域 | 实体产品生产、周边和库存管理 | 生产完成入库，容量不足有明确处理 |
| 服务器机房 | 在线游戏、订阅业务的服务容量 | 容量变化影响承载率及服务质量 |
| 硬件研发及工作设施 | 主机设计、测试和硬件迭代 | 技术人员推动硬件项目，而非软件项目 |

| 编号 | 优先级 | 功能与规则 | 验收标准 |
|---|---|---|---|
| ROM-01 | P0 | 房间类型、必要设施、人数和工位容量 | 缺少必要设备时显示缺失项；补齐后自动恢复有效；员工数可大于工位数，但闲置人员有明确状态 |
| ROM-02 | P1 | 房间环境：舒适度、温度、噪声、卫生等配置项 | 增减设施后环境可视化与员工效果同步；叠加规则和上下限可测试；跨墙影响遵循配置 |
| ROM-03 | P1 | 多房间协同一个项目及任务排队 | 多个专业部门贡献归属同一项目；取消项目清理队列；主开发暂停时辅助任务按规则暂停或继续 |
| ROM-04 | P1 | 房间失效与恢复 | 删除入口或关键设备后停止非法产出；恢复条件后按剩余工作量继续，不重领阶段奖励 |
| ROM-05 | P1 | 房间复制与批量人员调整 | 复制房间仅复制布局和允许的配置，不复制员工、进度和收入；批量调整失败对象单独说明 |

## 6. 员工移动、寻路与设施使用

寻路算法只是本模块的一部分；可达性、目标预约、重规划和业务异常处理共同决定员工是否能工作。

## 10. 游戏项目创建与开发生命周期

### 10.1 产品定位字段

| 字段 | 策划含义 | 校验与结果 |
|---|---|---|
| 项目名称 | 当前产品展示名称 | 长度和重复提示；内部使用稳定编号 |
| 产品类型 | 原创、续作、资料片、衍生、重制等 | 决定关联产品、解锁条件和适用规则 |
| 游戏类型与副类型 | 玩法方向 | 受研究解锁限制，影响设计权重和受众 |
| 主题与副主题 | 内容题材组合 | 影响匹配、系列定位与受众重叠 |
| 目标人群 | 产品受众 | 参与市场需求和内容匹配计算 |
| 项目规模 | 工作量、费用、内容上限与风险 | 规模提高应真实改变至少这些成本维度 |
| 目标平台 | 装机量、技术约束、授权费用和分成 | 多平台不是简单相加用户量，需处理受众重叠 |
| 引擎与技术版本 | 开发基础和功能支持 | 确认后可追溯，不被外部更新偷偷覆盖 |
| 开发功能 | 可选玩法和技术功能 | 增加工作量与效果，受平台和引擎限制 |
| 系列或外部授权 | 品牌归属和授权范围 | 需拥有使用权；合同期限覆盖规定阶段 |
| 设计方向 | 多组设计滑条和资源投入 | 影响质量和受众适配，有分析学习过程 |
| 预算与计划日期 | 管理目标 | 与实际成本和进度比较，不保证一定按时 |

### 10.2 生命周期

建议状态：方案草稿 → 已立项 → 开发中 → 可结束开发/继续打磨 → 待发行 → 已上市 → 长期维护或销售衰退 → 停售/关服 → 历史归档；暂停、取消和合同失败为显式分支。

开发维度包括游戏性、画面、声音、技术及缺陷。专业部门可并行服务。设计、制作、测试可以作为管理视图或里程碑，但不把此前讨论的“固定三个串行阶段”认定为原作规则。

| 编号 | 优先级 | 功能与规则 | 验收标准 |
|---|---|---|---|
| DEV-01 | P0 | 建立项目草稿并显示预算、工作量、条件和风险 | 未确认可返回修改且不扣费；确认时重新校验平台、授权和资金；连点只创建一个项目 |
| DEV-02 | P0 | 按团队有效工作推进，并记录工资、授权及直接成本 | 无可用员工时停工；休息员工不产出；同一笔成本不同时重复计入公司支出和项目支出总账 |
| DEV-03 | P1 | 多项目并行和部门支援 | 不同项目进度独立；员工与设施不能超额贡献；项目列表可发现缺员和资源冲突 |
| DEV-04 | P1 | 增减功能、换平台及重新规划 | 只在允许阶段变更；预览额外工作、费用和返工；已发布产品的变更必须通过补丁或新产品 |
| DEV-05 | P0 | 暂停、恢复、取消与历史记录 | 暂停停止项目劳动消耗，仍按公司规则支付工资；取消释放员工和辅助任务，保留已发生费用 |
| DEV-06 | P0 | 完成条件与提前结束 | 正常完成满足最低条件；提前结束需明确提示缺陷、质量与合同风险；未完成项目不能走正常上市入口 |
| DEV-07 | P1 | 专业美术、声音、动作捕捉和质量保证投入 | 完成支援任务影响指定维度；费用真实发生；同一支援成果不会重复加入质量 |
| DEV-08 | P1 | 项目经验与类型熟练度 | 有效完成后增加对应经验；取消项目收益按配置；无成本重复创建取消不能刷满经验 |
| DEV-09 | P1 | 计划、实际与延期管理 | 显示预计完成日、当前速度和延误原因；计划日改变不修改合同约定日；人员变动后更新预测 |
| DEV-10 | P0 | 发行前检查与开发报告 | 报告含平台、引擎、成本、维度质量、缺陷、合同和发行准备；缺必要条件时无法上市且原因可定位 |

## 11. 设计选择、分析学习、质量与缺陷

### 11.1 设计决策

| 编号 | 优先级 | 功能与规则 | 验收标准 |
|---|---|---|---|
| DSN-01 | P1 | 类型—主题—目标人群—平台之间存在匹配关系 | 同资源的两组测试项目仅修改匹配关系，结果按设定发生差异；界面不把所有组合都描述为最佳 |

| DSN-03 | P1 | 不同类型具有不同理想方向，复合类型按配置合成 | 测试配置下理想组合优于严重偏离组合；复合权重归一化；未知配置不直接泄露全部答案 |

| DSN-06 | P1 | 历史经验能帮助决策但不保证永远成功 | 相同方案在不同趋势、市场和技术背景下预测不同；预测展示区间或不确定性，不承诺必赚 |

### 11.2 质量、测试和评价

| 编号 | 优先级 | 功能与规则 | 验收标准 |
|---|---|---|---|
| QUA-01 | P0 | 质量由各维度产出、匹配、技术、完成度和缺陷形成 | 输入与权重可追踪；结果被限制在有效区间；不存在非数、无穷值或负质量 |
| QUA-02 | P1 | 开发产生缺陷，质量保证消除缺陷 | 产生与修复同时发生时顺序稳定；修复不使缺陷为负；人数为零时不获得人工测试产出 |

| QUA-06 | P1 | 发布后补丁修复和改进 | 补丁消耗时间/费用；完成后改变当前产品状态并记录版本；原始上市评分与后续口碑分别保存 |
| QUA-07 | P1 | 开发报告解释主要成功或失败因素 | 至少展示设计匹配、技术、质量、缺陷、价格/市场中的主要影响；解释与计算记录不矛盾 |

## 12. 产品类型、版本衍生与目录管理

原作依据：官方商店明确列出网游、免费游戏、手机游戏、街机、资料片、衍生作品、年度版、合集、廉价版、复古游戏、续作、重制和移植。具体依赖与收益规则以下表为本项目规格。

| 编号 | 优先级 | 产品与规则 | 验收标准 |
|---|---|---|---|
| PRD-01 | P0 | 原创单机：建立新产品与新系列，按次销售 | 成功上市形成独立产品编号；销售、成本和系列贡献可分别查询 |
| PRD-02 | P1 | 续作：关联前作并继承部分品牌认知 | 不复制前作销量或全部质量；前作口碑影响首发潜力；续作过密时按配置产生疲劳反馈 |
| PRD-03 | P1 | 衍生作品：沿用系列品牌并可改变类型定位 | 保留系列关系；类型经验按实际类型计算；主系列和衍生销量可分别查看 |
| PRD-04 | P1 | 资料片：依附本体并扩展内容 | 合法购买群体受本体拥有者限制；缺本体配置时无法发行；可用平台必须与本体兼容 |
| PRD-05 | P1 | 独立资料片：允许独立购买的扩展产品 | 与普通资料片使用不同购买前提；关联品牌但独立计价和记账；规则在创建页明确 |
| PRD-06 | P1 | 移植：将现有作品适配新平台 | 禁止向已存在同版本的平台重复移植；适配有时间和技术成本；销量受新平台需求及重叠用户影响 |
| PRD-07 | P1 | 重制/复刻：以历史作品为基础采用更新技术 | 原产品和新产品各自保留记录；需要权利；提高技术不自动获得完美口碑；上市后不覆写原作统计 |
| PRD-08 | P1 | 年度版：整合本体和符合条件的扩展内容 | 内容清单清晰；组件缺失或权利不足无法发行；不能把打包件误当成多次完整销售 |
| PRD-09 | P1 | 合集：多个已有产品组成商业包 | 不允许同一组件重复加入；各组件权利和分成有效；按配置分摊收入，包收入等于各分配项之和 |
| PRD-10 | P1 | 廉价版：成熟产品以较低价格再次销售 | 与首发版存在时间或价格条件；影响旧版需求；不重新获得原创开发奖励 |
| PRD-11 | P2 | 复古游戏：为旧平台或复古市场开发产品 | 可绕过普通退市平台的默认禁入仅限明确规则；目标市场规模独立估算；无复古条件时禁止发行 |
| PRD-12 | P2 | 街机产品：面向街机市场并关联相应生产/发行成本 | 不使用家用平台装机量直接计算全部销量；产品和设备成本计入对应账目；补产可追踪 |
| PRD-13 | P2 | 手机游戏：移动市场与适用商业模式 | 仅能选择兼容平台与功能；移动产品的受众和价格曲线独立配置；不默认等同免费网游 |
| PRD-14 | P2 | 大型多人在线游戏：持续服务器、维护、用户与内容运营 | 上线需要服务能力；停售新购和关服区分；长期收入不复用单机首发收入重复入账 |

| PRD-16 | P1 | 产品目录、生命周期与停售 | 可按状态、类型、平台、系列筛选；停售后停止新增销售，保留历史与未结算合同；库存处理明确 |

| 编号 | 优先级 | 功能与规则 | 验收标准 |
|---|---|---|---|

| SAL-07 | P1 | 收入预测、保本点与实际对比 | 预测注明假设；测试收入低于成本时显示亏损；售出单位利润非正时不显示错误的有限保本套数 |
| SAL-08 | P1 | 停售后的尾款、退款、授权费和维护义务 | 停售不再生成新成交；已有应收应付继续结算；停服另行处理；重复停售不会清空债务 |

建议计算链：潜在可购人群 → 市场份额与曝光 → 产品转化率 → 渠道/库存约束 → 实际销量 → 含退款的销售额 → 合同分成与成本 → 产品利润。各系数和随机项独立配置并保留计算摘要。禁止未经验证便使用“评分直接等于销量”的单一关系。

## 20. 公司财务、贷款与经营风险

本节为游戏内经济模型，不涉及现实投资建议。采用“现金、收入、费用、库存价值、应收应付”分开的口径，保证玩家能理解有利润却缺现金的情况。

| 编号 | 优先级 | 功能与规则 | 验收标准 |
|---|---|---|---|
| ECO-01 | P0 | 全部资金变化通过统一账本，包含原因、对象、时间和交易编号 | 任意时间段期末现金等于期初加净现金变动；禁止无来源加减钱；同交易编号重试不重复记账 |
| ECO-02 | P0 | 建造、薪资、租金、维护、研发、授权、营销和生产支出 | 每项可从总账定位业务来源；汇总与明细一致；员工薪资不得同时作为额外项目现金支出再次扣款 |
| ECO-03 | P0 | 周期性工资与入离职折算 | 按约定整期或按日在合同中明示；月中离职按该规则结算；月结前存档后读取不重复发工资 |
| ECO-04 | P1 | 贷款额度、利息、期限、还款与信用 | 借款只增加现金和负债，不计产品收入；还款减少负债和现金；利息与本金分开；额度不足不可借款 |

## 32. 数值平衡与策略验收

商业模拟的正确性和趣味性需分开验证。公式没有错误仍可能产生唯一最优解、无限套利或无法理解的失败。

| 编号 | 优先级 | 要求 | 验收标准 |
|---|---|---|---|
| BAL-01 | P1 | 标准难度存在多条可生存策略 | 合同驱动、小团队精品、系列经营、自发行扩张四种预设策略，在20个固定种子、相同10年期限下各至少12局避免破产；自动代理能力与操作规则随结果登记 |
| BAL-02 | P1 | 投入有取舍 | 培训、研发、营销、扩员和生产的收益有不同滞后与风险；不能在全部测试场景中由一个投入方向同时支配其他方向 |
| BAL-03 | P1 | 无可重复无限套利 | 买卖家具、报价变更、引擎授权、系列转移、自动补产、取消订单及联机赠送专项测试均不能凭重复操作无成本增加资产 |
| BAL-04 | P1 | 难度提供可解释压力 | 使用同一测试策略，难度升高应通过明确参数提高经营压力；失败报告能指出现金、质量、定位或市场问题 |
| BAL-05 | P1 | 长期发展不因单一指数永久失控 | 在100年模拟中记录资金、粉丝、用户和价格；不存在溢出、负值或无市场上限的无限新增用户 |
| BAL-06 | P1 | 新手失败有预警与学习反馈 | 资金危机至少提前一个设定结算周期提示；首作报告给出可操作改进建议；玩家能找到主要亏损来源 |
| BAL-07 | P2 | 后期业务有持续管理价值 | 主机、在线产品和子公司均需维护、内容或方针决策；不能建成后永久零成本正收益；允许合理自动化减少重复点击 |

上述成功率为设计调优目标，不应为“让测试通过”而给测试种子特殊规则。人工试玩需补充自动策略无法评估的节奏、理解成本和重复劳动体验。
