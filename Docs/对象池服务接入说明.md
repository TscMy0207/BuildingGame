# 对象池服务接入说明

## 方案与入口

底层使用Unity 2022.3自带的UnityEngine.Pool.ObjectPool<GameObject>，没有新增第三方依赖
Framework统一提供：

| 接口或文件 | 职责 |
| --- | --- |
| IObjectPoolService | 全局对象池入口，使用根容器依赖 |
| IScopeObjectPoolService | 当前模块独占的对象池入口，使用模块容器依赖 |
| IPooledObject | 业务组件可选的取出和回收通知 |
| Framework/Pooling/ObjectPoolService.cs | Unity对象池、资源所有权和实例生命周期 |
| Framework/Scope/ScopeObjectPoolService.cs | 模块隔离与Scope自动释放 |
| FrameworkComposition.RegisterDefaults | 全局单例及IStartupService注册 |
| ScopeModule.Configure | 模块池的Scoped注册 |
| FrameworkSettings.ObjectPoolMaxInactiveCount | 每个池的空闲实例缓存上限，默认64 |

全局对象池在资源服务之后启动，池按首次使用创建，无需额外场景或预制体宿主
每个模块拥有独立池集合，同一地址可以在不同模块各自建池，但实例绝不跨Scope复用

## 基本使用

业务类通过VContainer注入IObjectPoolService；模块业务优先注入IScopeObjectPoolService
两者使用相同方法：

```csharp
// 地址必须是已经配置到YooAsset采集包中的实际预制体
const string PreviewLocation = "Building/Assets/GameData/Buildings/PlacementPreview.prefab";

// 预热为至少8个空闲实例，不会调用OnEnable或OnSpawned
await pools.PrewarmAsync(PreviewLocation, 8, cancellationToken);

// 首次使用会异步加载，以后复用同一池
GameObject preview = await pools.SpawnAsync(
    PreviewLocation, parent: previewRoot, cancellationToken: cancellationToken);

// 业务参数在取出后设置，不能把上次借用的数据当作当前数据
preview.transform.position = worldPosition;

// 配对归还给借出它的同一个服务
bool returned = pools.Despawn(preview);

// 清理会销毁该池全部活动和空闲对象，并等待资源引用释放
await pools.ClearAsync(PreviewLocation);
await pools.ClearAllAsync();
```

示例Building资源包和PlacementPreview地址仅用于说明，项目没有自动创建这些业务素材
实际使用前，应先把自己的预制体加入YooAsset采集包，并将包加入项目的资源初始化配置
不要手动释放池持有的预制体资源引用

## 生命周期顺序

首次创建：

1. 加载一次预制体资源并建立池记录
2. 在停用的空闲节点下创建实例，显式保持实例停用
3. 使用池所属容器InjectGameObject完成根节点和子节点的依赖注入
4. 缓存实例中实现IPooledObject的组件
5. 取出时设置父节点并恢复预制体局部位置、旋转和缩放
6. SetActive(true)，触发适用的Awake和OnEnable
7. 调用IPooledObject.OnSpawned

普通回收：

1. 检查实例是否由当前服务借出
2. 调用IPooledObject.OnDespawned
3. SetActive(false)
4. 移回停用的空闲节点并恢复局部变换
5. 归还Unity池；空闲缓存已满时销毁该实例

依赖只在首次创建时注入，复用时不重复注入
预热只创建空闲实例，不调用取出或回收回调
父节点未激活时，SetActive(true)不会让实例立即变成activeInHierarchy，业务需自行保证显示层级有效

业务组件可实现IPooledObject：

```csharp
/// <summary>
/// 建筑预览的每次借用状态
/// </summary>
public sealed class PlacementPreview : MonoBehaviour, IPooledObject
{
    /// <summary>
    /// 重置上次借用残留的数据
    /// </summary>
    public void OnSpawned()
    {
        // 重置显示状态，再由调用方填写本次预览数据
    }

    /// <summary>
    /// 清理本次借用产生的临时状态
    /// </summary>
    public void OnDespawned()
    {
        // 取消计时器、解除临时事件、停止特效
    }
}
```

池不会自动重置刚体速度、Animator参数、粒子、事件订阅、异步任务和自定义业务字段
回调按创建时收集的组件列表执行，运行时新增组件不会自动加入回调列表
单个回调异常会通过项目日志记录并继续通知其他组件
注入、激活、停用及池回调期间禁止重入同一服务的池操作；需要生成或回收其他对象时，将操作安排到回调结束后
不要在回调内销毁自身、销毁池宿主或主动修改宿主层级

## 资源与取消规则

- 同一服务、同一资源地址只持有一次预制体加载引用
- 同地址的并发首次请求共享一次加载
- 回收到空闲缓存时继续持有引用，避免下次取出重复加载
- ClearAsync和ClearAllAsync销毁该范围内的活动及空闲对象，并等待Unity延迟销毁后再归还引用
- 清理期间再次请求同地址可以创建新池，旧池和新池各自管理资源引用
- 多次清理可同时等待，资源只配对释放一次
- 调用方取消只取消本次等待，已发起的共享加载会继续，并缓存到当前服务生命周期
- 加载期间清池或服务释放，加载完成后不会创建实例，取得的引用会配对归还
- Dispose立即停用并安排销毁实例，异步等待结束后归还引用；需要确认清理完成时可继续等待ClearAllAsync
- 模块Scope释放自动调用Dispose；手动卸载模块资源时应先等待该模块的ClearAllAsync
- 全局框架退出仍按现有资源服务释放流程执行，不依赖下一帧继续运行来保证进程退出时的资源回收

## 使用边界

- 只允许Unity主线程调用，不用于后台线程的托管对象池
- 同一实例只能归还一次；重复归还、外部对象、其他模块对象返回false
- 使用Despawn回收，不以SetActive(false)代替，也不应直接Destroy池对象
- 已被外部销毁的空闲实例会跳过，下次取出重新创建
- 外部销毁池宿主不属于支持的正常使用方式，需要清池后重建
- 没有提供延迟回收、自动过期或强制抢占活动对象，避免未经需求确认增加业务策略
- 64仅为空闲缓存上限，不是同时借出的数量限制
- 预热数量应不超过空闲缓存上限，数量过大会抛出参数异常
- 保持稳定资源地址，路径别名不会自动合并成同一个池
- 适合建筑预览、飘字、提示标记、短时特效和重复UI条目
- Master Audio播放对象由音频插件自身管理，不应交给本服务
- 长期存在的建筑、员工以及存档数据无需默认池化
